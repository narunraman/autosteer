How elements are made

An element turns one skill, like computing consumer surplus, into as many questions as you like, each with a correct answer.

Before you start

  • Find the gap. Look through the Dashboard for the skill you have in mind. What should a model be able to do that no element asks yet?
  • Think code first. Decide what varies (the numbers, the setting), how the correct answer follows from them, and which wrong answers are tempting. Write that as a generator, the filler, in filler_tools/. Then write a question that makes sense around it.
  • Never let a model write an answer. Every answer is computed by the filler. Models only help with wording.
def consumer_surplus(metadata):
    a, b, price = draw()           # what varies
    answer = (a - price)**2 / (2*b) # computed, never written
    return {"price": price, …, "options": tempting_wrong(answer)}
↓ a question around it

…What is your consumer surplus if the price is price?

Everything a model sees is a template like this one: fixed wording with {placeholders} the filler fills.

The order we support

Each element gets four steps in the app. This order has worked well for us.

1

Example seeds by hand

Write a few questions yourself, with {placeholders} where the filler's values go. Give each a domain, type and difficulty.

2 AI✓

Seed candidates a model writes, you verify

A model rewrites your seeds for other domains and perspectives. The AI check fills each one and asks a model to answer it; a miss usually means unclear wording.

You accept, edit or reject every candidate. Only accepted ones go on.

3 { }

Templates a model writes, from accepted candidates

The templates the sampler fills to make questions. One template becomes as many questions as you like.

4

Review you read

Read a fixed sample of the templates, filled (2% of them, at least 10, at most 20), and mark each fine or a problem. Then send the element on; see Review and submission.

py

Instead of steps 1 to 3

Write the templates in code

When the wording depends on the numbers (a payoff table, a story that changes with the draw), write the templates in the filler module and go straight to Review.
